# Tableau II Révisé : Conventions de Nommage (Propositions 16 à 35)

Suite à la recherche approfondie sur les meilleures pratiques de Godot 4.x, notamment concernant les Custom Resources (CR) et les conventions de nommage officielles, voici la version révisée des propositions 16 à 35.

| # | Type | Proposition Révisée | Fichier(s) Impacté(s) | Détail de la Convention | Justification (Basée sur Godot 4.x) |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **16** | **CR Fichier** | Définir une convention de nommage stricte pour les **fichiers Custom Resources (.tres)** : `[type]_[nom_instance].tres` en `snake_case`. | `CONVENTIONS_ASSETS_GENERAUX.md` | Ex: `item_wood_log.tres`, `building_stone_wall.tres`. | **Alignement Godot 4.x :** Les fichiers doivent être en `snake_case`. Le préfixe `CR_` est abandonné pour le fichier, mais le type est conservé. |
| **17** | **CR Classe** | Définir une convention pour les **classes Custom Resources (.gd)** : `[Type]Definition` ou `[Type]Data` en `PascalCase`. | `conventions_codage.md` | Ex: `ItemDefinition`, `BuildingData`. Le fichier GDScript correspondant sera en `snake_case` (ex: `item_definition.gd`). | **Clarté :** Utiliser un suffixe explicite (`Definition`, `Data`) pour distinguer les classes de données des classes de logique. |
| **18** | **Nommage Fichiers** | Maintenir l'obligation du `snake_case` en minuscules pour tous les noms de fichiers et dossiers de documentation. | `conventions_nommage.md` | Ex: `systeme_combat.md`, `gestion_workflow.md`. | **Standard Godot/Linux :** Assure la compatibilité et suit la convention des fichiers GDScript. |
| **19** | **Nommage Fichiers** | Maintenir la formalisation des préfixes numériques (ex: `01_`) pour les dossiers et fichiers du GDD et TDD. | `conventions_nommage.md` | Ex: `01_systeme_monde`, `02_biomes_et_environnement.md`. | **Ordre Logique :** Crucial pour la navigation dans la documentation structurée. |
| **20** | **Nommage Scènes** | Ajouter un préfixe de type pour les **fichiers de scènes Godot (.tscn)** : `SCN_` pour les scènes principales, `UI_` pour les interfaces, `PRFB_` pour les préfabriqués de nœuds. | `CONVENTIONS_ASSETS_GENERAUX.md` | Ex: `SCN_MainMenu.tscn`, `UI_InventorySlot.tscn`, `PRFB_EnemySpawner.tscn`. | **Clarté :** Le `PascalCase` est conservé pour les scènes, mais le préfixe améliore la classification dans l'explorateur de fichiers. |
| **21** | **Nommage Textures** | Standardiser le nommage des textures : `[asset_name]_[map_type]_[variant].png` en `snake_case`. | `CONVENTIONS_ASSETS_GENERAUX.md` | Ex: `colon_idle_albedo.png`, `colon_idle_normal.png`, `wall_stone_orm.png`. | **PBR Standard :** Utiliser des types de map PBR standard (`albedo`, `normal`, `orm` (Occlusion, Roughness, Metallic)). |
| **22** | **Nommage Audio** | Étendre les préfixes audio : `mus_` (musique), `sfx_` (effets sonores), `voc_` (voix/dialogues). | `CONVENTIONS_ASSETS_GENERAUX.md` | Ex: `mus_main_theme.ogg`, `sfx_chop_wood.wav`. | **Clarté :** Utiliser des préfixes courts et explicites. |
| **23** | **Typage Code** | Rendre obligatoire le **typage statique explicite** pour les arguments de fonction, les valeurs de retour et les variables membres de classe. | `conventions_codage.md` | Ex: `var health: int = 100`, `func get_name() -> String:`. | **Meilleure Pratique Godot :** Améliore la performance, la lisibilité et l'autocomplétion. |
| **24** | **Nommage Privé** | Définir une convention pour les variables et fonctions privées (internes à la classe) en GDScript : utiliser un **underscore de tête** (`_variable_privee`). | `conventions_codage.md` | Ex: `var _current_state`, `func _update_logic():`. | **Standard Godot :** Indique clairement que l'élément est interne et ne doit pas être appelé de l'extérieur. |
| **25** | **Nommage Singletons** | Formaliser l'utilisation de `PascalCase` pour les **Singletons** (AutoLoad) et s'assurer que leur nom de fichier (`snake_case`) et leur nom de classe (`PascalCase`) sont cohérents. | `conventions_codage.md` | Ex: Classe `GameManager` dans le fichier `game_manager.gd`. | **Standard Godot :** Les classes sont en `PascalCase`, les fichiers en `snake_case`. |
| **26** | **Chemins de Nœuds** | Exiger l'utilisation de la syntaxe abrégée `$NodeName` ou `get_node("NodeName")` pour les chemins de nœuds, et **interdire** les chemins absolus (`/root/...`). | `conventions_codage.md` | Ex: `$Player/Camera3D`. | **Robustesse :** Évite les erreurs de référence lors de la réorganisation des scènes. |
| **27** | **Nommage Énumérations** | Définir une convention pour les **énumérations** en GDScript : Nom de l'énumération en `PascalCase`, membres en `SCREAMING_SNAKE_CASE`. | `conventions_codage.md` | Ex: `enum ItemType { WOOD, STONE, METAL }`. | **Standard Godot :** Aligne avec les conventions de constantes. |
| **28** | **Nommage Signaux** | Exiger que les signaux soient nommés au **passé** pour les événements terminés (ex: `item_collected`) ou au **présent** pour les actions en cours (ex: `is_moving`). | `conventions_codage.md` | Ex: `signal health_changed(new_value)`. | **Sémantique :** Clarifie le moment où le signal est émis. |
| **29** | **Nommage Modèles 3D** | Intégrer les conventions de nommage des modèles 3D (ex: `SM_` pour Static Mesh, `SK_` pour Skeletal Mesh, `COL_` pour Collider) dans `docs/GDD/10_design_artistique/modelisation_3d/conventions_nommage_modeles.md`. | `conventions_nommage_modeles.md` | Ex: `SM_Wall_Stone.fbx`, `SK_Colon_Male.fbx`. | **Standard Industrie :** Facilite l'intégration dans le pipeline 3D. |
| **30** | **Nommage Matériaux** | Définir une convention pour les matériaux Godot : `MAT_[NomAsset]_[Type].tres` en `PascalCase`. | `CONVENTIONS_ASSETS_GENERAUX.md` | Ex: `MAT_Wood_PBR.tres`. | **Clarté :** Utiliser un préfixe `MAT_` pour les ressources de matériaux. |
| **31** | **Nommage UI** | Définir des préfixes pour les éléments d'interface utilisateur (UI) dans les scènes Godot (ex: `Btn_`, `Lbl_`, `Pnl_`, `HBox_`). | `conventions_codage.md` | Ex: `Btn_StartGame`, `Lbl_HealthValue`. | **Lisibilité Scène :** Facilite la lecture de l'arbre de scène et l'accès par `$`. |
| **32** | **Nommage Fichiers** | Ajouter une règle pour les fichiers temporaires ou d'exemple : préfixer par `_temp_` ou `_example_`. | `conventions_nommage.md` | Ex: `_temp_test_data.json`. | **Hygiène du Dépôt :** Évite l'intégration accidentelle. |
| **33** | **Nommage Fichiers** | Exiger que les fichiers de données externes (XML, JSON) soient nommés en `kebab-case` ou `snake_case` (choix à faire). **Proposition :** Utiliser `snake_case` pour l'uniformité avec les fichiers GDScript. | `conventions_nommage.md` | Ex: `game_data_items.json`. | **Uniformité :** `snake_case` est le standard pour les fichiers Godot. |
| **34** | **Nommage Groupes** | Ajouter une section sur les conventions de nommage des **Groupes** Godot : Utiliser `snake_case` et un préfixe de domaine. | `conventions_codage.md` | Ex: `group_enemies`, `group_ui_panels`. | **Standard Godot :** Les groupes sont souvent utilisés pour les collections de nœuds. |
| **35** | **Nommage Constantes** | Définir une convention pour les **constantes mathématiques** ou physiques : `SCREAMING_SNAKE_CASE` avec un préfixe de domaine. | `conventions_codage.md` | Ex: `MATH_PI`, `PHYSICS_GRAVITY`. | **Clarté :** Distingue les constantes du jeu des constantes génériques. |
